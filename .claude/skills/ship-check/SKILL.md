# Ship check

Push в `main` сразу выкатывает сайт на dev.bm-klus-bv.nl. Прод выкатывает только владелец: GitHub → Actions → «Deploy prod (Antagonist Slim)» → Run workflow. Задача — ответить «можно / нельзя / можно с оговорками» и показать доказательства.

## Шаги
1. **Состав изменений**: `git status`, `git diff --stat`, непушнутые коммиты — `git log origin/main..HEAD --oneline`. Раздели изменения, которые влияют на сборку или деплой (`app/`, `components/`, `lib/`, `hooks/`, `styles/`, `data/`, `public/`, `deploy/`, `scripts/`, `.github/workflows/`, `package.json`, оба lock-файла, `next.config.mjs`, `postcss.config.mjs`, `tsconfig.json`), и остальное (`seo-ops/`, `docs/`, инструкции) — остальное на сайт не влияет. В изменениях не должно быть секретов (`.env*`, ключи, токены) и мусора (временные файлы, скриншоты, `*.stackdump`).
2. **Типы**: `npx tsc --noEmit` — 0 ошибок.
3. **Сборка**: `pnpm build` — без ошибок. Затем по `out/` (команды `grep` — в Git Bash):
   - каждая новая или изменённая страница есть: `out/<путь>/index.html`;
   - `out/sitemap.xml` содержит новые URL и не содержит удалённых;
   - в HTML изменённых страниц нет цен: `grep -oE "vanaf ?€|€ ?[0-9][0-9.,]*"`. Допустимы только `priceRange` «€€» в схеме и экономия энергии (`gemiddeldBesparing`) на городских страницах;
   - `<title>` изменённых страниц без обрезки «…», description ≤ 160.
4. **Изображения** (если менялись): вес новых вариантов в `public/images/` в пределах бюджетов пресета (`docs/IMAGE-PIPELINE.md`), новые ключи есть в `data/image-manifest.json`.
5. **Зависимости** (если менялся `package.json`): обновлены оба lock-файла — CI ставит пакеты через `npm ci` по `package-lock.json`.
6. **Редиректы** (если менялся `deploy/apache/root.htaccess`): формат строк как у соседних; файл уйдёт на dev с push и на прод со следующим ручным деплоем.
7. **Вид** (если менялась вёрстка): страница открыта в dev-сервере на десктопе и мобильной ширине.

## Ответ владельцу
- Вердикт: можно / нельзя / можно с оговорками — и почему.
- Что проверено и с каким результатом; что не проверялось и почему.
- Что попадёт на dev после push и что — на прод только после ручного запуска workflow.
- Если нужны действия владельца — точные команды или клики. Коммит и push — только по его явной команде.
