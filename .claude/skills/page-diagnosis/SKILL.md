# Диагноз страницы

Правила анализа — `seo-ops/CLAUDE.md`; факты, границы данных, рынок — `seo-ops/knowledge.md`; что уже делали — `seo-ops/data/decision_log_v1.csv`.

## Данные — от дешёвого к дорогому
1. **Запросы страницы**: `seo-ops/snapshots/normalized/seo/gsc_query_page_last90d.csv` и `…_last28d.csv`. Старше 7 дней — сначала skill `seo-refresh` или живой запрос через MCP `gsc` (`search_analytics`, `dimensions: query`, `pageFilter` на URL). Сгруппируй запросы по подинтентам, бренд отдельно.
2. **Страница как есть**: title / description — `data/sitemap-plan.ts` (города — `lib/content/gevelisolatie-locations.ts`, проекты — override в `page.tsx`); текст и структура — где лежит, см. `CLAUDE.md` («Архитектура»); бриф — `seo-system/briefs/` (у вложенных страниц — `<родитель>-<дочерняя>.yaml`, есть не у всех). Живая версия — `curl -sL https://bm-klus-bv.nl/<путь>/`: прод деплоится вручную и может отставать от репозитория.
3. **Индексация**: MCP `gsc` → `index_inspect` (verdict, coverageState, lastCrawlTime).
4. **Соседи**: какие ещё URL получают показы по тем же запросам — критерий каннибализации в `seo-ops/CLAUDE.md`.
5. **История**: строки журнала решений по странице, `git log` по её файлам (это даты коммитов; дата выката на прод — по запускам deploy-prod, см. `seo-ops/CLAUDE.md`), границы из календаря в `knowledge.md`.
6. **Выдача** по 1–3 главным запросам, если без неё не понять интент: skill `serp-check` (копейки).

## Ответ владельцу (по-русски)
- Что проверено: источники и окна.
- Диагноз: факты с метками → интерпретация с уверенностью → гипотезы и как их проверить.
- 3–6 действий по приоритету и что делать не стоит (например, переписывать сильную страницу целиком).
- Нужен файл — `seo-ops/reports/seo/<slug>_diagnosis_<YYYY-MM-DD>.md`.
